# 弱点集中課題 R-07: ACL順序・NAT方向 + SSL証明書連携 + SSH制限

**対象範囲**: ACL順序・NAT方向（過去ミスの反復潰し）、CA証明書発行＋nginxリバースProxy、SSHの送信元IP制限
**目安時間**: 90〜120分
**背景**: 第13〜20回の過去問分析で判明した「出現頻度は高いが手薄な領域」だけを1本にまとめた課題。round19環境（R-Tky1/R-Tky2/R-Gnm・osv1/osv2）をそのまま流用

## 要件

### フェーズ0: ターミナル環境設定（R-Tky1・R-Tky2・R-Gnm 全台）

以下を暗記で投入すること（詳細はCLAUDE.md参照、コマンド自体はここに書かない）：
- ホスト名（機器名に合わせる）
- 特権モードパスワード
- DNSルックアップ無効化
- コンソール回線: ログ同期・タイムアウト無効
- タイムゾーン(JST)
- ターミナル表示行数（無制限）

### フェーズ1: R-Tky1（ここが今回の最重要ポイント）

1. インタフェースにIPアドレスを設定（上表の通り）
2. デフォルトルートをISP側に設定
3. `192.168.1.0/24`（t-client側）への静的経路をR-Tky2経由で設定
4. **静的NAT**: tsv(10.100.0.1)を`201.10.0.3`へ変換
5. **外部インタフェース(Gi0/0)着信ACL**を以下の通り設定:
   - 発信トラフィックの戻りを許可する（`established`）
   - tsv上のDNS・Web・SMTPサービスへのトラフィックを許可する
   - tsv自身への**エコー要求**（pingが飛んでくる方向）を許可する
   - R-Tky1自身への**エコー要求**を許可する
   - 上記以外は全て拒否する

   **⚠️ 過去に繰り返したミスなので、書く前に意識すること**:
   - `eq <ポート番号>`は宛先アドレス(`host 201.10.0.3`)の**後**に書く。送信元(`any`)の後ろに書くと「送信元ポート指定」という別の意味になる
   - 「外から中へのping」を通したいなら`echo`（request）。`echo-reply`は逆方向
   - `deny`は`permit`より**先**に書く。特に「上記以外は拒否」を実現する`deny ip any any`は、他のACL行の**後**（末尾）に置く

### フェーズ2: R-Tky2

1. インタフェースにIPアドレスを設定
2. IPv4のデフォルト経路をR-Tky1に設定
3. tsvで稼働しているDHCPサーバが`192.168.1.0/24`（Internal）へサービスを提供できるようDHCPリレーを設定

### フェーズ3: R-Gnm

1. PPPoEクライアントをCHAP認証で設定（MTU 1492指定を忘れずに）
2. `192.168.1.0/24`へDHCPサーバを設定（範囲は任意、`.254`は自インタフェース分を除外）
3. 動的NAT(NAPT)で`192.168.1.0/24`から外部への通信をDialer0経由で変換

### フェーズ4: サーバ証明書 + リバースProxy（osv1・osv2）

1. **証明書の入手**: `http://200.99.1.1/osaka19/`から`server_ca.crt`（サーバ証明書）と`server.key`（秘密鍵）をダウンロードする（`wget`または`curl`でosv1に取得）
   - このURLはCA(`sv`)が既に発行済みの証明書を公開している場所。CN/SANは`sec.osaka-skills.jp`
2. **osv1にnginxをインストール**し、以下を設定:
   - `https://sec.osaka-skills.jp/`へのリクエストをHTTPS終端で受け、ダウンロードした証明書・秘密鍵を使う
   - リバースProxyとしてosv2(192.168.1.1)の80番ポートへリクエストを転送する（osv1-osv2間は平文でよい）
3. **osv2にapache2をインストール**し、上記リバースProxyからのリクエストに対しバックエンドとして応答する（表示内容は任意の固定文字列でよい、例:"Back-end Server"）
4. DNS(bind9)未構築でも構わないので、動作確認は`/etc/hosts`や`curl --resolve`で代用してよい

### フェーズ5: SSHの送信元IP制限（osv2）

1. osv2にopenssh-serverをインストール（未インストールなら）
2. TCP 10022番ポートでサービス提供
3. 公開鍵認証のみ許可（パスワード認証は禁止）
4. **`192.168.2.0/24`（Internal2、o-client側）ネットワーク内のノードからのみ接続を許可する**
   - 実装方法は`sshd_config`の`Match Address`か`/etc/hosts.allow`+TCP Wrappersが機能しないDebian新しめの版なら`iptables`/`sshd_config`側で制御する
   - **前回の教訓**: `/etc/hosts.allow`はDebian 9以降のopenssh-serverでは機能しない

## 終了後の確認観点

- ACLは`show ip access-lists`で行の並び順まで確認する（意図通りの順序か目視）
- NATは`show ip nat translations`で実際に変換されているか確認する
- quota系と同様、SSH制限も「設定した」で終わらせず、**許可されるべきでない場所から実際に拒否されることまで確認する**（前回の教訓: 見た目は正しくても機能していないことがある）
