# 単発ドリル R-07: ACL順序

**対象範囲**: 拡張ACLの記述順序のみ
**目安時間**: 10〜15分
**背景**: 4月〜7月に一貫して繰り返した唯一のミスパターン。今回はACL単体に絞って精度を上げる

---

## トポロジー

```
[ISP] ── Gi0/0 [R-Tky1] Gi0/1 ── (tsv, 10.100.0.1)
既設定・触らない        まっさら
```

console: R-Tky1 = `telnet 192.168.0.15 5008`（write erase済み）
tsv: 10.100.0.1（背景、触らない。DNS/Web/SMTPが既に動いている）

---

## IPアドレス

| インタフェース | アドレス |
|---|---|
| Gi0/0(Fa0/0) | 201.10.0.2/29（ISP側） |
| Gi0/1(Fa0/1) | 10.100.0.254/24（tsv側） |

---

## 要件

1. インタフェースにIPアドレスを設定、デフォルトルートをISP側(201.10.0.1)へ
2. **静的NAT**: tsv(10.100.0.1)を`201.10.0.3`へ変換（ACL動作確認に必要な最小限のNATのみ）
3. **Gi0/0(外部)着信ACL**を以下の順で意識して作成:
   - 発信トラフィックの戻りを許可（`established`）
   - tsv上のDNS・Web・SMTPサービスへのトラフィックを許可
   - tsvへの**エコー要求**を許可
   - R-Tky1自身への**エコー要求**を許可
   - 上記以外は拒否

**チェックポイント（過去のミス）**:
- `eq <port>`は宛先(`host 201.10.0.3`)の**後**
- pingを外から通したいなら`echo`（`echo-reply`ではない）
- `deny`は他のpermitより**後ろ**（末尾）

---

## テストコマンド

| テスト | 期待結果 |
|---|---|
| `show ip access-lists`で行の並び順を目視確認 | permit群→deny ip any anyの順 |
| 外部からtsv(201.10.0.3)へping | 通る |
| 外部からR-Tky1(201.10.0.2)へping | 通る |
| 外部からtsvのWeb(80)へアクセス | 通る |
| 外部からtsvの未許可ポート(例: 22)へアクセス | 通らない |
