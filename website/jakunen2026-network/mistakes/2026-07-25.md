# 2026-07-25: オフラインaptリポジトリの不備

私(Claude)側のミス — osv1/osv2/osv3向けオフラインaptリポジトリの構築・運用不備

## 自作ISOの`Packages`ファイルのパスが二重(`pool/pool/`)になっていた
- 症状: `sources.list`に`deb [trusted=yes] file:/media/cdrom0/pool/ ./`を設定してもbind9がインストールできない
- 原因: 自作したISOの`Packages`ファイルの`Filename:`欄が`pool/xxx.deb`という記述だったが、sources.listで`file:/media/cdrom0/pool/ ./`のように`pool/`を既にベースパスとして指定していたため、実際のパス解決が`pool/pool/xxx.deb`と二重になり見つからなかった
- 教訓: `dpkg-scanpackages`で生成した`Packages`ファイルの`Filename:`欄のパスと、実際にsources.listで指定するベースパスの整合性を確認する

## `_apt`ユーザーがCD-ROM経由のファイルを読めなかった(パーミッション)
- 原因: `_apt`(aptがサンドボックス実行する権限を落としたユーザー)が`/root`配下や、読み取り専用CD-ROM経由のシンボリックリンクを読めなかった(パーミッションエラー、errno 13)
- 対処: `/tmp/localrepo/`のような誰でも読める場所に実体コピー(`cp -L`、シンボリックリンクではなく)し、パスを修正した`Packages`を再生成することで解決

## 正しい手順(以後この構成を使う場合の標準手順)
```
mount /dev/sr0 /media/cdrom0
mkdir -p /tmp/localrepo && chmod 755 /tmp/localrepo
cp -L /media/cdrom0/pool/*.deb /tmp/localrepo/
sed 's|^Filename: pool/|Filename: |' /media/cdrom0/pool/Packages > /tmp/localrepo/Packages
gzip -9c /tmp/localrepo/Packages > /tmp/localrepo/Packages.gz
chmod 644 /tmp/localrepo/*
echo 'deb [trusted=yes] file:/tmp/localrepo/ ./' > /etc/apt/sources.list.d/offline.list
mv /etc/apt/sources.list /etc/apt/sources.list.bak   # ネット向けを無効化(重要)
apt-get update
```

## CD-ROM未マウント状態での`apt install`がハングする問題(osv2で発生)
- 症状: `apt-get install`が「could not get」のような症状で固まる
- 原因: CD-ROMがまだマウントされておらず、インターネット向けの`sources.list`だけが有効な状態で`apt install`を実行すると、ネットに繋がらない`https`メソッドプロセス(`_apt`)がタイムアウトせず残り続けて固まる
- 対処: CD-ROMのマウント・オフラインリポジトリ設定・インターネット向けsources.listの無効化(`mv`でバックアップ)を最初に必ず行う。この事象はosv1・osv2・osv3の3台とも共通して発生した

## 教訓
- 独自のオフラインリポジトリ(自作ISO)を使う場合、パスの二重解決とパーミッションの2点は特にハマりやすい。1台で解決した手順は必ずhandoff.mdのような形で記録し、他の同じ構成のVMにもそのまま適用する
- 「ネットが繋がらないはずの環境で、なぜかネット向けの接続を試みて固まる」という症状が出たら、まず`sources.list`にネット向けのエントリが残っていないか確認する
