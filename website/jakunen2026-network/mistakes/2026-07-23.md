# 2026-07-23: R-Tky・R-Kgw1・R-Kgw2 ACLレビュー

学習者側のミス — R-Tky・R-Kgw1・R-Kgw2 演習レビュー(1時間・ノーヒント)で発見

## R-Tky

- **`ip helper-address`が逆のインタフェースに付いていた**: Fa0/1(tsv側)に付けていたが、DHCPクライアント(t-client)がいるFa1/0側に付けるのが正解。broadcastを中継する側＝クライアント側のインタフェースに設定する
- **ACLの宛先ポート指定位置ミス**: `permit tcp any eq domain host 10.100.0.1`のように書くと、`eq domain`は直前の`any`(送信元)のポート指定として解釈され、「送信元ポート53」という意味になってしまう。正しくは宛先(`host 10.100.0.1`)の後に書く: `permit tcp any host 10.100.0.1 eq domain`
- **ICMPの許可行が全部`echo-reply`になっていた**: 外部からのping要求(echo)を通す要件なのに、逆方向(echo-reply=自分から出したpingの戻り)だけ許可していた。原文が「〜へのエコー**要求**トラフィックを許可する」なので`echo`が正解
- 「R-Tky自身へのエコー要求許可」の行が丸ごと抜けていた
- NATプールのnetmaskが`/24`だったが、実際のFa0/0は`/29`なので`255.255.255.248`が正確
- DNSの許可がTCPのみで、UDPが抜けていた

## R-Kgw1(IPv6)

- **デフォルトルートが`ipv6 route ::/64 ...`になっていた**(致命的ミス、最優先で修正が必要だった): `::/64`だと実質何も経路が通らない。正しくは`ipv6 route ::/0 ...`
- R-Tkyと同じ、ACL宛先ポート位置のミス(`eq domain`/`eq www`が送信元ポート扱い)
- ICMPが`echo-reply`になっていた(同じ問題)
- 「R-Kgw1自身へのping許可」の宛先が`::1`(ループバック)になっていた。正しくはR-Kgw1自身の実アドレス`2001:DB8:3:1::1`

## R-Kgw2(PPPoE、時間切れで一部未完了)

- CHAP認証情報(`ppp chap hostname`/`ppp chap password`、ppp-user/R7pass)が入力中に崩れて未設定のままだった
- `Dialer0`に`dialer pool 1`の紐付け(Fa0/0の`dial-pool-number 1`と対応させる設定)が無かった
- DHCPプールに配布範囲の制限(`ip dhcp excluded-address 192.168.1.21 192.168.1.254`)が無く、`.1`〜`.253`全てが配布対象になっていた
- 動的NAT(PAT)は未着手だった

## 教訓
- **`eq`のポート指定位置**と**`echo`/`echo-reply`の向き**は、3台ともに共通して出た間違い。「宛先アドレスの後に宛先ポートを書く」「外から中へのpingを通したいなら`echo`(request)」という2点を意識して覚え直すと一気に直る
- IPv6のデフォルトルートは`::/0`。`::/64`という一見似た書き方との違いに注意（`/64`は単なる大きなサブネットの経路であって「どこへでも」という意味にはならない）
