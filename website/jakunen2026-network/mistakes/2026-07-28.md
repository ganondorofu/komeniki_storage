# 2026-07-28: DNS/メール周りの背景インフラ不備

## 私(Claude)側のミス — 背景インフラ(tsv/sv/osv1/osv3等)の構築不備

これらは全て採点対象外の背景環境（私が構築・管理する範囲）で見つかった不備。学習者の演習ミスではない。

### allow-recursion / match-clients に「実際のクライアントのセグメント」を入れ忘れる、が繰り返し発生
- tsv・sv・osv1・osv3の4台全てで同じ抜けがあった
- 症状: 特定のセグメントのクライアントからだけ`query refused`になる
- 教訓: bind9で`allow-recursion`や`view`の`match-clients`を書くときは、実際に問い合わせてくる全クライアントセグメントを漏れなく列挙する。1台直したら関連サーバー全てに同じ抜けがないか横展開して確認する

### dovecot: `10-auth.conf`に`!include auth-system.conf.ext`を入れ忘れ、passdb未設定でauthプロセスがクラッシュ
- 症状: POP3ログイン時に`-ERR Auth process broken`
- ファイル自体(`auth-system.conf.ext`)には正しい設定があったのに、includeし忘れていた

### dovecot: `10-mail.conf`に`namespace inbox { inbox = yes }`を書き忘れ
- 症状: 認証は成功するのに直後に`namespace configuration error`で切断

### postfix: `smtpd_relay_restrictions`の互換性式が空値評価になりsmtpdがクラッシュループ
- `postconf`の出力に`${{$compatibility_level}...}`という動的式が残っており、評価結果が空になっていた
- `postconf -e`で明示的な値に上書きして解決

### mynetworksの古いIPの消し忘れ
- svのIPアドレスを`172.20.0.0/24`→`200.99.1.1/24`に修正した際、`mynetworks`だけ更新し忘れていた

### bind9が動いているのに`/etc/resolv.conf`が空
- tsv・svの両方で、システムの標準リゾルバ設定が空のまま放置されていた
- `nmcli connection modify <conn> ipv4.dns 127.0.0.1 ipv4.ignore-auto-dns yes`を設定し忘れていた

### 外部から内部ドメインを参照する設定で、プライベートアドレスを指定してしまった
- svからtokyo-skills.jp(tsv)宛メールを配送する際、forward先にtsvの実アドレス(`10.100.0.1`)を指定してしまい到達不可
- 正しくは静的NAT変換後のグローバルアドレス(`201.10.0.3`)を指定する必要があった

### sv: `/var/www/html/`(www.itnetsys.org)にindex.htmlを作り忘れ
- game/secretディレクトリには作成していたのに、htmlディレクトリだけ抜けていて403エラーになっていた

### 証明書発行時にSAN(Subject Alternative Name)拡張を付け忘れた
- CA構築時、CNのみで発行しておりSAN拡張が無かった
- モダンブラウザ(Chromium系)はSAN必須のため`ERR_CERT_COMMON_NAME_INVALID`で拒否される
- `-extfile`で`subjectAltName=DNS:<hostname>`を指定して再発行し解決

### squidの稼働ホストを勘違いして案内した
- 実際にはosv2で動いているのに、osv3のアドレスをプロキシ先として案内してしまった

### VXLAN越しのセグメント(vmbr5)でMTU不一致
- ホスト側(node1/node2)のvxlan5/vmbr5のMTU設定が1500のままで、本来必要な1450になっていなかった
- `ip link set vxlan5/vmbr5 mtu 1450`で解消（ただし大きいファイルのsamba転送は別要因で依然不安定、多重仮想化環境の限界として保留）

## 学習者側のミス — 演習作業でのつまずき

### Thunderbirdのメールアドレス(Identity)欄とサーバー名を混同
- サーバー名(`mail.tokyo-skills.jp`)とメールアドレスのドメイン(`tokyo-skills.jp`)を混同し、`alice@mail.tokyo-skills.org`→`alice@mail.tokyo-skills.jp`→最終的に`alice@tokyo-skills.jp`と複数回の修正が必要だった
- 教訓: 「サーバー名」と「メールアドレスのドメイン」は別物として扱う。`mail.`はサーバー名にのみ付き、メールアドレスには付かない

### httpsでアクセスするURLを勘違いしていた
- `secret.itnetsys.org`用の証明書をインストールしたのに、実際には`https://www.itnetsys.org/`(SSL非対応、httpのみのサイト)にアクセスしようとしてエラーになっていた
- 教訓: 証明書エラーが出たら、まず「本当にそのURL・プロトコルでアクセスすべきなのか」を要件と照らし合わせて確認する

### R-TkyのACL編集で、既存の`deny`より後ろに新しい`permit`を追加してしまった
- 名前付きACLを`no ip access-list extended NAME`せずに追記していくと、新しい行は既存の`deny`より後ろに追加される
- `deny`が先に評価されるため、後から追加した`permit`が無効化されていた
- 教訓: 途中に`deny`がある名前付きACLに行を追加する際は、シーケンス番号を明示して`deny`より前に挿入する

### ACLを修正した後`write memory`を忘れ、ルータの予期しない再起動で修正が消えた
- 演習用ルータの設定は、直したらその場で`write memory`しないとNVRAMに保存されない
