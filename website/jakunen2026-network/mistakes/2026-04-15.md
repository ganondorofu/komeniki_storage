# 2026-04-15

## IPv6 ACL ルール順の誤り

**状況**: BLOCK_WAN_IPV6 ACLで R-WAN（2001:db8:1::1）からの通信を拒否したかった

**誤った順番**:
```
permit icmp any any nd-na
permit icmp any any nd-ns
deny ipv6 host 2001:db8:1::1 any  ← 後ろにあるので評価されない
permit ipv6 any any
```

**正しい順番**:
```
deny ipv6 host 2001:db8:1::1 any  ← 先に書く
permit icmp any any nd-na
permit icmp any any nd-ns
permit ipv6 any any
```

**原則**: 詳細（狭い範囲）なルールほど先に書く。IPv4 ACLも同じ。

## IPv6 ACLの適用インタフェース

**誤り**: Dialer0 inbound に適用しようとした

**正解**: Fa0/1 inbound

**理由**: IPv6アドレス（2001:db8:1::2/64）はFa0/1に直接設定されているため、IPv6トラフィックはFa0/1を通る。Dialer0はIPv4 PPPトンネル専用。

コマンド: `ipv6 traffic-filter BLOCK_WAN_IPV6 in`（Fa0/1配下）

## ACL sequence番号の残留

**状況**: `no sequence X` で個別削除したとき一部が残り、新しいエントリが後ろに追加された

**対策**: `no ipv6 access-list ACL名` で全削除してから再作成する
